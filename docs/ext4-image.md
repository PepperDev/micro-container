# Ext4 Image Generation

The ext4 loopback image is written entirely in C (`src/ext4/`) — no templates or
external tools. The layout is modeled on `mke2fs -Text4 -m0 -i65536 10G` output,
with one intentional difference: **no `lost+found`** directory (only root inode 2).

The image is generated by `ext4_create_img()` which writes all structures from
scratch with a random UUID and checksums. `s_mtime` is set to 0 so `dumpe2fs`
shows "n/a" for Last mount time (the image was never mounted).

### Hardcoded Geometry (10 GiB)

| Parameter | Value | Derivation |
|-----------|-------|------------|
| Image size | 10737418240 (10 GiB) | |
| Block size | 4096 (4 KiB) | `s_log_block_size = 2` |
| Blocks | 2621440 | `image / block_size` |
| Groups | 80 | `ceil((blocks - 2) / 32768)` |
| Blocks per group | 32768 | |
| Inodes per group | 2048 | |
| Inodes total | 163840 | `groups × inodes_per_group`; matches `image / 65536` bytes-per-inode |
| Inode table / group | 128 blocks | `2048 × 256 / 4096` |
| Inode size | 256 | |
| Desc size | 64 | required by `EXT4_FEATURE_INCOMPAT_64BIT` |
| Reserved GDT | 1024 | as mke2fs computes for 80 groups |
| Journal | 64 MiB (16384 blocks) | internal, inode 8 |

### Feature Flags (mke2fs reference)

```
compat     = 0x0000103c   HAS_JOURNAL | EXT_ATTR | RESIZE_INODE | DIR_INDEX | ORPHAN_FILE
incompat   = 0x000022c2   FILETYPE | EXTENTS | 64BIT | FLEX_BG | CSUM_SEED
ro_compat  = 0x0000046b   SPARSE_SUPER | LARGE_FILE | HUGE_FILE | DIR_NLINK | EXTRA_ISIZE | METADATA_CSUM
```

Cage matches all the above. `FLEX_BG` incompat is set with `s_log_groups_per_flex = 4`
(16 groups/flex), and `s_reserved_gdt_blocks = 1024` — both as mke2fs produces for
this geometry. `ea_inode` (compat 0x2000) is intentionally absent.

### Backup Superblocks

Backup superblocks are written in every `has_super()` group (1, 3, 5, 7, 9, 25,
27, 49, …). Unlike the primary, a backup superblock sits at the **start** of the
group's first block (`group × 32768 × 4096`, offset 0); the 1024-byte `SB_OFF`
applies only to group 0. The backup GDT copy occupies the next two blocks of the
group. `s_block_group_nr` and the CRC32C checksum are recomputed per group.

### Checksum Seed

All metadata checksums use CRC32C (polynomial 0x82F63B78) with a seed derived
from the filesystem UUID:
```
csum_seed = CRC32C(~0, uuid[0..15])
```
This matches e2fsprogs' behavior when both `METADATA_CSUM` and `CSUM_SEED` features
are set (both are set in our layout).

### Verification

The image passes `e2fsck -fn` and matches `dumpe2fs` / `debugfs` output against
`mke2fs` from e2fsprogs 1.47.3 for all verified fields.

Every backup superblock must also pass `e2fsck -b <group × 32768> -fn`; a plain
`e2fsck -fn` never reads backups. Without the correct offset the kernel logs
`Invalid checksum for backup superblock <blk>` at mount-time resize.
